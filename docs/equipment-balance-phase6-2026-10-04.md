# 裝備重設 V1.0：存檔、八欄預算與真實補藥流程

狀態：修復一項正式讀檔遺失問題，其餘仍為離線候選與實際引擎診斷；整套實裝未完成。未 push、merge、deploy。

## 已修復：穿戴裝備的鑲嵌資料

實際 serializeGameForStorage → JSON.parse → restoreGame 回歸發現 sanitizeEquip 重建穿戴物品時漏掉 socketGem。原能力與 magic 並沒有因此被重新計算，但寶石持有量、原始名稱及每部位100顆上限資訊消失，後續可繼續加工而突破上限。

- game-save-normalizers.ts 恢復有效 socketGem 的 ID、名稱、数量、累積能力、原始裝備名稱；不再次加能力，不重算品質、強化或核心。
- 原核心、+15、品質、保底值、來源、屬性和詞條保持原路徑。缺失或格式錯誤的寶石 metadata 安全忽略，不抹除物品或既有 bonus。
- 測試涵蓋主角武器／ring2、出戰與休息傭兵、背包、重複正規化；實際鑲嵌100顆後讀檔仍拒絕第101顆，保留原始名稱，沒有重複能力。
- 不能從已經丟失 metadata 的存檔猜回寶石種類／數量；本修復不是追溯性補償，也未改玩家實際儲存資料。

## 非破壞舊装預覽

equipment-conversion-preview.ts 收集背包、主角全欄、出戰／休息傭兵與外部明示的共享倉庫；200件背包測試無截斷。現有商隊背包沒有有限容量，不製造假背包滿規則。

只接受明確提供的唯一 UID 與定義對應，不從名稱或 UID 前綴猜物品；未知對應、重複 UID、多個對應、非法等級／品質／強化／部位留原物品。存在詞條、契印、寶石、技能、属性或抗性的裝備，只給核心參考，不能偷偷變普通裝。原物品深拷貝保留，預覽不寫存檔。

此為純離線 review。definitionId 尚未由正式新物品 registry 驗證；沒有正式 UI、備份／確認／套用／還原操作，也沒有回收價預覽或補償。不可稱為完成 migration。

## 八欄整套預算

正式裝備欄位是 weapon、helm、armor、gloves、amulet、boots、ring1、ring2。之前七件曲線與連戰證據只戴一枚戒指，不是八欄滿裝。

新增 curveDraftFullEquipment：維持整套預算，原飾品攻擊／HP拆成兩枚相同預算的戒指，均向下取整；因此整套最多少1攻／1HP，不額外加第二份飾品能力。同款可重複穿戴，不依賴禁戴同款或指定左右戒指來維持上限。品質／強化在每枚基底之後只乘一次，仍是离线烘焙數值，沒有正式 schema 或 balanceVersion。

測試全部1–250級八欄總核心不超預算、每部位單調、兩戒同值、UID不重複，以及金色+15核心4倍。另以八欄普通裝混編四人、七個真實怪物、每個30種子，共210場首戰：各目標皆30/30勝利且全員存活。目標為Lv.36夜蝠、56毒蛛、72山魈、112甲蟲、162鎖山衛、212毒蟒、250咒吏。這不是全怪物、Boss、長期養成或離線的通關證據。

七件歷史比較保留，measure-equipment-curve 與 audit-equipment-auto-potion 增加明示 fullSlots 參數。現行八欄對照是另外穿一枚現行同款戒指，候選八欄則分攤預算，兩者不可混成舊七件結果。

## 真實自動補藥測量

audit-equipment-auto-potion.mjs 呼叫實際購藥、設定、start-auto-hunt，以及每200ms settleCurrentGame → applyAutoPotionAction。購買100枚當前金創藥（單價600），用完停補藥，沒有免費再補貨或每場回滿。保留實際 EXP、升級、金錢收益與 Battle Log。鎖定怪物 ID，任何重生後目標漂移立即報錯；最初未鎖定目標的結果作廢，不用其數字評估高階怪。

最新八欄測量：四個等級、現行／候選、30%補藥門檻、五個種子，40組，各觀察10分鐘或首次進入 recovering。

重要限制：人工同級四人、60萬未賺取的初始金錢、略過引導／旅行、最大普通怪編制、沒有隨機材料／兵符／裝備掉落；沒有補魔／補貨或返城再出發。金錢包含離線收益函式的準點計算；netGoldAfterConsumedPotions 只扣已消耗藥品，不是扣完100枚購藥庫存投資的現金盈餘。這不是新角色30分鐘、瀏覽器真實時間或離線模擬。
