## 2. 目前完成度摘要

目前已完成遊戲的主要可玩循環：建立角色、編成隊伍、進入地圖、進行戰鬥、取得戰利品、強化裝備、獲得放置收益，以及重新載入本機存檔。

目前定位為「核心玩法已建立的可玩原型」，尚未達到正式發布品質。最大的未完成區域是首領技能與狀態效果的即時戰鬥整合、測試整理，以及雲端存檔／帳號系統。

## 4. 目前已知問題

### 4.1 高優先度：戰鬥整合

- 首領的護盾、風碎、恢復術、火焰燎原、詛咒等技能資料已存在，但尚未完整接入即時戰鬥引擎。
- 天照五件套的特殊被動尚未完整接入即時戰鬥。
- 戰鬥畫面中的護盾／恐懼圖示仍讀取舊戰鬥時間戳，可能不會正常啟用。
- 前排攻擊加成與後排閃避規則在即時戰鬥中尚未完全套用。
- 2026-09-12 排查確認：程式碼中搜尋 aggregate／legacy／old／deprecated 均無結果，先前「舊版 aggregate battle 與 realtime battle 並存風險」的警告已過時，判定舊系統已不存在，此風險項目移除。
- 舊版 aggregate battle 的未呼叫程式已移除；後續新增技能須只接入現行 realtime 路徑，避免重複傷害。

### 4.2 測試與品質

- 2026-09-12 實測：163 項中 133 項通過、30 項失敗；新增 3 項怪物 ID／數值來源測試與 1 項共用防禦公式測試皆通過。`pnpm exec tsc --noEmit --pretty false` 與 `pnpm build` 通過；建置仍提示大型 client chunk。
- 明確過時的失敗包括舊 5 名傭兵上限（現為 11 名）、舊回合制／手動攻擊測試，以及舊商路隨機遭遇規則。其餘失敗仍需逐項核對，尤其材料交易、客棧和角色升級，不應直接視為舊測試。
- 即時引擎已測同時起始事件、目標重選、時間分段一致性、終局事件不重複，以及副本獎勵只發放一次；副本層已測狂虎減速與流血狀態到期。其他首領技能與狀態效果尚未完整接入即時引擎，其到期測試仍待補。
- 原先記載的 TypeScript 錯誤實際有 8 項，均位於現行 `app/` 程式碼，已修正；本次檢查沒有發現重複專案樹造成的 TypeScript 錯誤。
- 2026-09-14：商團領地相關 4 項測試通過，`pnpm exec tsc --noEmit --pretty false` 與改動檔案 oxlint 通過。全專案 lint 仍有既有檔案錯誤；客棧測試 2 項失敗，分別是舊測試載入主角升級函式失敗與對舊版程式文字的比對，不是領地療傷規則測試失敗。

### 4.3 資料與命名

- 2026-09-12 已排查怪物資料架構：確認 monster-ecology.ts 的 ECOLOGY_MONSTERS 為主要怪物資料庫，dungeon-engine.ts 的 DUNGEONS 透過展開語法引入，屬合理設計；gersang-world-map.ts 提供關卡掉落表，也非重複資料。唯一發現的例外是 thug(打手)寫死在 dungeon-engine.ts，已搬移進 ECOLOGY_MONSTERS 統一管理，並通過 build 驗證。
- 2026-09-12 已修正：mythic-forge.ts 中 amaterasuStaff(天照法杖)變數名稱與其實際內容(T10 天照頭盔，slot為helm)不符，已統一改名為 amaterasuHelm，並同步更新 game-save-normalizers.ts 的引用。玩家存檔相容邏輯(舊名稱「T10 天照神杖」的字串比對)維持不變，已通過 build 驗證。
- 44 種可戰鬥怪物以穩定 ID 對應：HP、MP、攻擊、經驗值只在 `monster-ecology.ts` 定義；地圖、掉落與展示資料由 `v17-content.ts` 補充。另 8 種舊商路怪物沒有副本 ID，保留原有資料。世界地圖及怪物抗性語意仍分散，待後續統一。
- 部分網站標題與產品名稱仍可能保留舊版本文字。
- 2026-09-12 已確認並移除：game-data.ts 裡的 cities(25筆舊城市資料)經排查確認完全沒有任何檔案引用，屬於死程式碼，已安全刪除並通過 build 驗證。目前實際使用的城市資料來源為 15-data.ts 的 worldCities。

### 4.4 環境與工具

- `vinext`（beta 1.0.0-beta.5）套件本身依賴宣告不完整（缺少 `vite-plugin-commonjs`），需靠 `.npmrc` 的 `shamefully-hoist=true` 設定繞過 pnpm 嚴格隔離機制。
- 專案不可放在 OneDrive 或其他雲端同步資料夾底下開發，會導致 pnpm 安裝過程被鎖檔中斷。
- Build 過程偶爾會出現 `vinext:og-inline-fetch-assets` 外掛異常耗時（曾發生一次近 20 分鐘的建置延遲），原因可能與大型音檔被內嵌為 base64 有關，需留意觀察。

## 7. 每次開發後的更新規則

每次修改或新增功能後，請同步更新本文件：

1. 在「已新增與完成的功能紀錄」新增一列。
2. 記錄實際修改日期，格式為 `YYYY-MM-DD`。
3. 寫明修改類型：新增、修改、修正、重構、刪除或驗證。
4. 記錄主要檔案與目前狀態。
5. 進行 Git commit，commit 訊息應描述本次變更。
6. 若測試或建置結果改變，更新「測試與品質」段落。

## 9. Godot 轉向評估（2026-09-12；目前暫停）

目前決策：**先完成網頁版，不建立或並行開發 Godot 專案。** 以下移植原則、素材盤點與工時估算僅作歷史評估；未來若重新啟動，再依當時的網頁版規格更新計畫。

### 9.1 移植原則

- React／TypeScript 介面、Phaser 地圖和現有 JavaScript 戰鬥流程無法直接作為 GDScript 執行；Godot 版須重新建立場景、介面、狀態管理與規則實作。
- 核心資產是**設計規則與測試案例**：角色／傭兵數值、戰鬥公式、攻擊順序、冷卻、MP、掉落率、成長曲線、商路與離線結算。移植前應固定相同輸入下的預期輸出，尤其是四捨五入、隨機數、時間推進與獎勵發放時機。
- 目前網頁版已具備角色建立、三欄存檔、主角加最多 11 名傭兵、城市、商路、地圖、即時戰鬥、掉落、背包和裝備等主要可玩循環。Godot 專案檔 `project.godot`、`.gd`、`.tscn` 目前尚不存在。
- 怪物、掉落與地圖資料分散在多個網頁模組；移植前先定出一份權威資料表，保留穩定 ID，再匯入 Godot。`app/equipmentSkill.js` 與 `app/monsterAssets.js` 是獨立輔助模組，目前仍未接入主要遊戲流程，不應將其視為已完成的 Godot 規則。

### 9.2 素材與存檔

- 本工作區的 `public/assets` 約有 3,009 個檔案、28.9 MiB，包括 2,866 個 WebP、87 個 PNG、44 個 GIF、5 個 JPG、4 個 MP3，另有 JSON／SVG。Godot 可匯入常見 PNG、JPEG、WebP、SVG 與 MP3；GIF 不在官方常規圖片匯入清單中，需挑選要用的動畫並轉為影格或 spritesheet。素材路徑亦須從網站 `/assets/...` 改為 Godot 資源路徑 `res://...`，並重設切圖、動畫與音樂播放。
- 不應直接將 3,009 個素材全部塞進首個試作；先選一個地圖、一種普通怪、一名首領與少量角色。搬移前確認素材使用及再散布權限。
- 現有玩家進度存在瀏覽器 `localStorage`。Godot 應建立具版本號的存檔格式；若需保留舊玩家進度，另做網頁版匯出 JSON／Godot 匯入 JSON。Godot 的 `user://` 不會自動讀到舊 `localStorage`。

### 9.4 先前的移植順序（已暫停）

以下是先前評估時提出的步驟，目前不執行。若未來重啟，應先以當時網頁版的首領技能、狀態效果、前後排規則與首領數量重新確認規格。

1. 固定一場可重播戰鬥的輸入與預期事件／傷害／掉落，並確定存檔欄位和規則版本。
2. 建立獨立 Godot 專案；以資料定義、純 GDScript 戰鬥模型、場景呈現和存檔服務分工。
3. 完成單張地圖的完整循環，使用相同測試資料比對網頁版與 Godot 版。
4. 驗證首領技能、狀態到期、離線結算及獎勵只發放一次後，再逐步移入城市、商路和完整內容。

若 Godot 版仍以瀏覽器為目標，應從第一個試作即驗證 Web 匯出。Godot 4 的 C# 專案目前不能匯出 Web，因此此路線優先採 GDScript。瀏覽器背景分頁會暫停處理，放置收益應依重新開啟時的時間差結算；Web 版 `user://` 的持久化依賴瀏覽器 IndexedDB 設定。
