## 2. 目前完成度摘要

目前已完成遊戲的主要可玩循環：建立角色、編成隊伍、進入地圖、進行戰鬥、取得戰利品、強化裝備、獲得放置收益，以及重新載入本機存檔。

目前定位為「核心玩法已建立的可玩原型」，尚未達到正式發布品質。最大的未完成區域是首領技能與狀態效果的即時戰鬥整合、測試整理，以及雲端存檔／帳號系統。

## 4. 目前已知問題

### 4.1 高優先度：戰鬥整合

- 首領的護盾、風碎、恢復術、火焰燎原、詛咒等技能資料已存在，但尚未完整接入即時戰鬥引擎。
- 天照五件套的特殊被動尚未完整接入即時戰鬥。
- 戰鬥畫面中的護盾／恐懼圖示仍讀取舊戰鬥時間戳，可能不會正常啟用。
- 前排攻擊加成與後排閃避規則在即時戰鬥中尚未完全套用。
- 必須避免同時啟用舊版 aggregate battle 與 realtime battle，否則可能造成重複傷害。

### 4.2 測試與品質

- 現有測試紀錄為 153 項中 123 項通過、30 項失敗。
- 部分失敗是舊規格測試，例如舊隊伍人數、舊回合制戰鬥和舊隨機遭遇規則。
- 仍需補上即時戰鬥的引擎層測試：同時起始事件、目標重選、狀態到期、傷害分段一致性與獎勵只發放一次。
- TypeScript 仍有舊模組／重複專案樹相關錯誤，需要分辨哪些是現行程式問題。

### 4.3 資料與命名

- 怪物、掉落、世界地圖資料分散於多個來源，長期可能造成資料不一致。
- `amaterasuStaff` 與「天照頭盔」的命名仍有遺留不一致。
- 部分網站標題與產品名稱仍可能保留舊版本文字。
- 舊的 20 城市資料仍存在，但目前 UI 只開放四大城市。

## 5. 尚未實作的範圍

- 帳號系統
- 雲端存檔
- 跨裝置自動同步
- 後端資料庫

目前所有遊戲狀態都在瀏覽器端，玩家可透過本機資料修改遊戲數值。

## 6. 建議開發順序

1. 將首領技能與狀態效果正式接入 `realtime-battle-engine.js`。
2. 補齊首領、前後排、狀態與獎勵的引擎測試。
3. 執行並整理完整測試，將過時測試與真正缺陷分開。
4. 統一怪物、掉落與世界地圖資料來源。
5. 修正天照裝備命名與網站產品標題。
6. 再決定是否加入 GitHub、雲端存檔與帳號系統。

## 7. 每次開發後的更新規則

每次修改或新增功能後，請同步更新本文件：

1. 在「已新增與完成的功能紀錄」新增一列。
2. 記錄實際修改日期，格式為 `YYYY-MM-DD`。
3. 寫明修改類型：新增、修改、修正、重構、刪除或驗證。
4. 記錄主要檔案與目前狀態。
5. 進行 Git commit，commit 訊息應描述本次變更。
6. 若測試或建置結果改變，更新「測試與品質」段落。
